# Security Policy

## Reporting a Vulnerability

We take the security of AgriChain seriously.

If you discover a security vulnerability in AgriChain, please report it responsibly and privately.

### How to Report

Please do **not** create a public GitHub issue for security vulnerabilities.

Instead, report the vulnerability privately by:

- Using GitHub's **Private Vulnerability Reporting** feature, if enabled.
- Or contacting the AgriChain security team through the private contact method provided by the maintainers.

### What to Include

Please include as much of the following information as possible:

- A clear description of the vulnerability
- The affected component, endpoint, or feature
- Steps to reproduce the issue
- Proof-of-concept code or request, if available
- The potential security impact
- Any suggested mitigation or fix

Please avoid including sensitive information such as real user passwords, private keys, access tokens, API secrets, or personal data.

## Scope

Security reports may include vulnerabilities involving:

- Authentication and authorization
- JWT and session handling
- Password handling and credential security
- API endpoints
- Database access
- WebSocket communication
- Payment processing and payment verification
- Input validation
- Access control
- Sensitive data exposure
- Injection vulnerabilities
- Server-side security issues

## Responsible Disclosure

Please give us reasonable time to investigate and address a reported vulnerability before publicly disclosing it.

We ask security researchers to avoid:

- Accessing, modifying, or deleting other users' data
- Disrupting or degrading the service
- Performing denial-of-service attacks
- Social engineering or phishing
- Accessing production systems beyond what is necessary to demonstrate the vulnerability
- Publicly disclosing the vulnerability before we have had an opportunity to address it

## Response

We will acknowledge valid security reports and investigate them as soon as reasonably possible.

We may request additional information to reproduce or verify the vulnerability.

## Security Updates

Security fixes will be released through the appropriate project release or deployment process.

Thank you for helping keep AgriChain and its users secure.
